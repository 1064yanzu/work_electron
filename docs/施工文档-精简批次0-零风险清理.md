# 施工文档：精简批次 0 —— 零风险清理（A1–A5）

日期：2026-08-12
依据：`docs/代码分析/精简决策方案.md`「批次 0」
性质：纯清理，不改任何运行时行为（除废弃 DB 表 DROP 外）

## 背景

决策方案将精简工作分为五个批次，批次 0 是其中风险最低的一组：
失效脚本、滞后 lockfile、零引用依赖、孤儿 DB 表、污染检索的参考目录。
本批目标是快速兑现这部分收益，并为后续批次（死代码删除、产品收敛、
结构收敛）清出干净的基线。

## 实施内容

### A1 失效 npm scripts

- `package.json`：删除 `sync:open-design` / `sync:open-design:update`
  两个 script。它们指向的 `scripts/sync-open-design.mjs` 不存在，
  执行必报错，属于明确的失效入口。

### A2 pnpm-lock.yaml

- 删除 `pnpm-lock.yaml`。项目以 npm 为准（`package-lock.json` 在维护），
  pnpm lock 严重滞后（如 agent-sdk 声明 ^0.2.72 vs 实际 ^0.3.222），
  留着只会误导。该文件未被 git 跟踪，无需额外清理索引。

### A3 零引用依赖 class-variance-authority

- `package.json` dependencies 移除 `class-variance-authority`。
- 验证：全仓（`src/` / `electron/` / 配置 / 脚本）零引用，仅在已移出仓库的
  `cherry-studio参考/` 与 lockfile 中出现。
- 已执行 `npm install` 同步 `package-lock.json` 并从 node_modules 卸载。
- 注：同批审计中的 `bufferutil` / `utf-8-validate` **保留不删**——
  它们是 `ws` 的 optional native 加速依赖（决策方案 B 节已明确）。

### A4 DB 孤儿表 workflow_nodes / workflow_run_logs（schema v8）

- 新增 `electron/main/db/migrations/v8Migrations.ts`：
  `DROP TABLE IF EXISTS workflow_run_logs` → `DROP TABLE IF EXISTS workflow_nodes`
  （先子表后父表；`idx_workflow_run_logs_node` 索引随表自动删除）。
- `electron/main/db/migrate.ts`：`CURRENT_SCHEMA_VERSION` 7 → 8，
  版本链追加 `if (currentVersion < 8)` 步骤。v8 只做 DROP、无独占新表，
  按 v3 先例不设哨兵表（漏检代价仅是孤儿表残留，无运行时影响）。
- `electron/main/db/migrations/initSql.ts`：移除两张表的 CREATE 语句
  （遵循 Wiki 表从 v1 移除的先例），留注释指向 v8。
  v2Migrations 中残留的 `CREATE INDEX ... ON workflow_run_logs` 有逐条
  try/catch，全新安装时静默跳过，不需要改动。
- `electron/main/services/backupPayload.ts`：`DEFAULT_BACKUP_TABLES`
  移除两表。导入逻辑本来就只写入「当前存在的表」，旧备份包中残留的
  workflow_* 数据会被安全跳过，向后兼容。
- `electron/main/services/incrementalBackup.ts`：同步两处注释中的表名。
- 连带删除前端死封装：`src/lib/api/workflow.ts` 调用的
  `create_workflow_node` / `list_workflow_nodes` 等 6 个 IPC 命令在主进程
  **从未注册过**（`electron/` 全仓零匹配），文件本身除 barrel 外无人引用。
  一并删除 `src/lib/api.ts` 的转发行与 `src/types.ts` 中的
  `WorkflowNodeType` / `NodeStatus` / `WorkflowNode` / `WorkflowRunLog` /
  `Create/UpdateWorkflowPayload` / `Append/ListWorkflowLog(s)Payload`
  类型（`NodeStatus` 经全仓 grep 确认仅被 workflow 类型引用）。

### A5 参考目录移出仓库

- `cherry-studio参考/`（725MB）与 `.references/`（62MB）移动到
  仓库外的 `/Volumes/external disk/develop/_reference-archives/`。
- 移动前已确认：两者均在 `.gitignore` 中（未被 git 跟踪）；
  `tsconfig.json` include 仅 `src` / `electron`；`electron-builder.json5`
  files 仅 `dist` / `dist-electron` / `package.json` / `node_modules`——
  本就不参与类型检查与打包，移动是纯收益（检索/统计/编辑器索引不再被污染）。

## 验证

1. `npm run typecheck`：通过（全绿）。
2. `npm run dev` 冒烟：应用正常启动，主进程服务（AutoSyncScheduler 等）
   初始化成功，无新增 crash 记录。
   - 注意：在本机 agent shell 中需 `env -u ELECTRON_RUN_AS_NODE npm run dev`，
     否则宿主环境注入的 `ELECTRON_RUN_AS_NODE=1` 会让 Electron 以纯 Node
     运行而报 `does not provide an export named 'BrowserWindow'`——
     这是环境问题，与本次改动无关（改动不触碰任何 electron 导入）。
3. v8 迁移在真实开发库上验证通过：
   `PRAGMA user_version` = 8；`sqlite_master` 中 `workflow%` 表已不存在。
