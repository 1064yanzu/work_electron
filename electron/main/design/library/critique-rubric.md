# 5 维设计自检契约

交付前对你自己的 HTML 设计稿做一轮自我评审，按以下 5 个维度各打 1-10 分，并附上修复清单。

## 评分维度

### 1. 哲学一致性 (Philosophy)
- 设计语言是否与所选**方向**或**系统**一致？
- 配色 / 字体 / 间距 / 形状是否表达了同一种态度？
- 风格漂移、混搭、自相矛盾会扣分。

### 2. 视觉层级 (Hierarchy)
- 第一眼吸引到的是不是页面最重要的信息？
- 字号 / 字重 / 颜色对比 / 留白是否服务于信息优先级？
- 一切都"差不多大"是层级失败。

### 3. 细节执行 (Execution)
- 对齐严格吗？8/4 网格守住了吗？
- 标点用对了吗（中文用「」""、破折号用 ——、不要 ASCII 替身）？
- focus / hover / disabled / empty state 全都想过了吗？

### 4. 功能性 (Functional)
- 信息传达是否清晰？读者 30 秒能 get 到要点吗？
- 移动端布局是否真的可用，而不是简单堆叠？
- 可访问性 (对比度 / 语义化 / 键盘可达) 全部达标？

### 5. 创新性 (Innovation)
- 有没有一个让人记住的细节？
- 是不是又写了一个 SaaS 落地页模板？
- 一个亮点远比五个安全选择更值钱。

## 输出格式（在 HTML 之外另出一段 Markdown）

```markdown
## 自检报告

| 维度 | 得分 | 主要问题 |
|---|---|---|
| 哲学一致性 | 8 | 一处按钮 hover 用了和品牌方向不一致的蓝色 |
| 视觉层级 | 7 | 三个 H2 字号差异不够明显 |
| 细节执行 | 9 | — |
| 功能性 | 8 | 移动端导航没收到汉堡 |
| 创新性 | 6 | 整体偏稳，没有惊艳点 |
| **总分** | **38/50** | — |

## 修复清单（按优先级）
1. 把 hover 蓝改成 #5E6AD2 与品牌一致
2. H2 用 clamp(24px, 4vw, 32px) 拉开层级
3. 移动端 nav 收到汉堡菜单
```

总分 **40+ / 50** 视为可交付；30-39 建议改一轮；30 以下重做。

## Self-Gate JSON 契约（用于 gateMode 自动重做）

如果调用方传入 `gate_mode: true`，在 5 维评分之外再输出一段严格 JSON：

```json
{
  "passed": false,
  "lowest_dim": "innovation",
  "lowest_score": 5,
  "regenerate_reason": "整体偏稳无亮点，建议在 hero 加一个让人记住的细节",
  "scores": { "philosophy": 8, "hierarchy": 7, "execution": 9, "functional": 8, "innovation": 5 },
  "total": 37,
  "notes": "...",
  "fixes": ["..."]
}
```

- `passed`：总分 ≥ 40 且每维 ≥ 6 时为 true
- `lowest_dim` / `lowest_score`：最弱维度 + 该维度得分
- `regenerate_reason`：一句话告诉下一轮该专攻什么

引擎拿到 `passed: false` 会触发一次 follow-up 自我重做（最多 3 轮）。
